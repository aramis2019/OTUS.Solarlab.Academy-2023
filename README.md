# Solarlab.Academy-2023
Учебный проект в рамках курса Соларлаб Академия Backend 2023

## Секреты

Секреты (ключ подписи JWT, пароль БД) в репозитории не хранятся.

- **docker-compose** берёт их из файла `.env` рядом с `docker-compose.yml` (он в `.gitignore`):

  ```
  cp .env.example .env
  # задать JWT_KEY (минимум 32 символа), например: openssl rand -base64 48
  ```

- **Локальный запуск API** (`dotnet run`, окружение Development) — ключ задаётся через user-secrets:

  ```
  cd src/Board/Host/Board.Host.Api
  dotnet user-secrets set "Jwt:Key" "<случайная строка не короче 32 символов>"
  ```

  Строка подключения к локальной БД лежит в `appsettings.Development.json`.

- В остальных окружениях — через переменные окружения `Jwt__Key` и `ConnectionStrings__PostgresBoardDb`.

Без `Jwt:Key` API не запустится.

Разрешённые для CORS источники задаются в `Cors:AllowedOrigins` (по умолчанию список пуст). Swagger доступен только в окружении Development.

## docker-compose 

- Для запуска контейнеров выполняем:

	`docker-compose up -d`
	
  Запускаются сервисы:
  - персистентный сервис для работы с БД (PostgreSQL), доступен только с локальной машины:
    - 127.0.0.1:5432
  - сервис миграций БД (при старте также хеширует пароли, оставшиеся в открытом виде от старых версий);
  - сервис WebAPI (прокидываем 80-й порт из контейнера на 5000-й порт локальной машины):
    - 5000:80
  - adminer, доступен только с локальной машины:
    - 127.0.0.1:8080

- Проверить состояние сервисов: 
  
  `docker-compose ps` 

- Отключение: 
  
  `docker-compose down` 
  
  (порты свободны, сохраняется **persisted volume** для БД).
